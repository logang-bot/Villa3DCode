Read all files in the docs/ directory: project-overview.md, roadmap.md, mission-design.md, mission-walkthrough.md, game-mechanics.md, and every file under features/.

Then give a structured session briefing in this exact format:

## Current Phase
One sentence on which milestone phase we are in and what percentage of it is done. If roadmap.md's "Next task" points at the mission build order (mission-design.md), describe progress in those terms instead (e.g. "N of 6 mission build-order items done, currently on item M") rather than the roadmap's Phase 1–4 milestones — those are deprioritized while mission work is the active focus.

## What's Built
Bullet list of completed systems — one line each, no script details, just what exists and works.

## Where We Left Off
One or two sentences describing the exact stopping point from the last session.

## Next Task
The single next thing to work on, with a one-sentence description of what it involves.

## Watch Out For
Any gotchas, key decisions, or non-obvious constraints from the docs that are relevant to the next task.

Be concise. This is a startup briefing, not a full documentation summary.
